# Machine-Readable Docs: `llms.txt` & `llms-full.txt`

**Last Updated:** July 9, 2026

This site publishes two plain-text files for AI agents and LLM crawlers, following
the [llms.txt convention](https://llmstxt.org/):

| File                                              | Purpose                                                                 |
|---------------------------------------------------|-------------------------------------------------------------------------|
| <https://docs.photoprism.app/llms.txt>            | Curated, machine-readable **index** of the whole documentation site.    |
| <https://docs.photoprism.app/llms-full.txt>       | Full-text **Markdown dump** of the User Guide and Getting Started pages. |

They mirror the equivalent files on the marketing website
(<https://www.photoprism.app/llms.txt>), which are produced by Hugo. Because this
site is built with MkDocs — which has no equivalent output-format mechanism — the
files here are generated by a small build hook instead.

## What Each File Contains

**`llms.txt`** — a header (title, one-line description, short intro, and a pointer
to `llms-full.txt`) followed by one `##` section per top-level nav section
(**Getting Started, User Guide, Developer Guide, About**). Each entry is a link to
a page, following nav order and hierarchy. The index covers the **whole** site.

**`llms-full.txt`** — the same header, then the full source Markdown of every page
under **Getting Started** and **User Guide**, in nav order. Each page block is:

```
# <Page Title>

Source: <canonical URL>

<page Markdown, with internal links and images rewritten to absolute URLs>

---
```

The Developer Guide and About sections are **linked** in `llms.txt` but are **not**
dumped in full — the dump is intentionally scoped to the end-user and admin content
that LLMs are most often asked about.

## How It Is Generated

A single build hook, [`hooks/llmstxt.py`](hooks/llmstxt.py), wired into
`mkdocs.deploy.yml` under `hooks:`. It adds **no third-party dependencies** and
reads the **raw source Markdown** directly (no HTML-to-Markdown round-trip), so the
output stays clean on our heavily-extended Material setup.

It is wired into `mkdocs.deploy.yml` only — not the base `mkdocs.yml` — because it
is a production-output concern (like the `privacy` plugin) and there is no need to
regenerate the files on every `properdocs serve` (`make watch`) livereload. `make build` and the CI
deploy both use `mkdocs.deploy.yml`, so both produce the files.

The hook uses three standard MkDocs events:

- **`on_files`** — builds a site-wide `src_uri -> absolute URL` map from the full
  file list (pages **and** static assets), used to resolve relative references.
- **`on_page_markdown`** — captures each page's raw source Markdown.
- **`on_post_build`** — walks the nav, assembles both files, and writes them into
  the built `site/` directory (so they are published at the site root).

### Link & Image Resolution

Source Markdown uses relative links (`[x](../foo/bar.md)`) and images
(`![alt](img/x.jpg)`) that only become public URLs when rendered. In
`llms-full.txt` these are rewritten to absolute URLs via the file map:

- **Links** to other pages resolve to their absolute canonical URL (anchors are
  preserved). A target that cannot be resolved falls back to its plain link text.
- **Images** resolve to their absolute asset URL. One that cannot be resolved falls
  back to a `[image: <alt>]` (or `[image]`) placeholder so the surrounding prose
  still reads sensibly.
- **Linked images** (`[![alt](img)](page)`) are handled as a unit — both the image
  and the link target are resolved.
- External links (`http(s):`, `mailto:`), already-absolute (`/…`) targets, and
  same-page anchors are handled correctly; trailing attr-lists (`{ .shadow }`) are
  stripped from the dump.

HTML comments (`<!-- ... -->`) are removed from `llms-full.txt` as well — they are
hidden on the rendered site, so commented-out sections should not surface in the
dump either.

## Adjusting Generation

All tunable values are constants at the top of `hooks/llmstxt.py`:

| Constant             | Effect                                                                   |
|----------------------|--------------------------------------------------------------------------|
| `FULL_TEXT_SECTIONS` | Top-level nav sections dumped in full into `llms-full.txt`. Default: `("Getting Started", "User Guide")`. The `llms.txt` index always covers every section. |
| `TITLE`              | `#` heading at the top of both files.                                     |
| `DESCRIPTION`        | The `>` one-line description.                                             |
| `INTRO`              | The prose paragraph after the description.                                |

To include another section in the full dump (e.g. the Developer Guide), add its
top-level nav title to `FULL_TEXT_SECTIONS`.

## Testing

Unit tests for the pure assembly and link-resolution logic live in
[`hooks/test_llmstxt.py`](hooks/test_llmstxt.py) and need no MkDocs install:

```sh
cd hooks && python3 -m unittest test_llmstxt
```

To verify end to end, run a production build and inspect the output:

```sh
make build                 # renders with mkdocs.deploy.yml into site/
head site/llms.txt
head site/llms-full.txt
```

The build log prints a summary line, e.g.
`llmstxt: wrote llms.txt (4 sections) and llms-full.txt (128 pages)`.
